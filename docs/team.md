## 배정 기준

- **E = 전체 확인 역할.** E는 모든 파트의 PR을 최종 확인하고 매주 금요일 통합 시연을 이끈다. 그래서 E의 구현 범위는 API·인증·저장·배포로 좁히고, 손이 많이 가는 데이터 작업(템플릿·카탈로그 수집)은 A로 옮겼다.
- **A = iOS + 데이터.** iOS 앱은 화면 4개 규모라 작업량이 적다. 대신 LiDAR 기기로 팀원 방을 실측하고, 카탈로그 25종(규격·가격·URL)을 시트로 수집해 E에게 넘긴다.
- **D = 엔진.** 점수 요소, LLM 설명, GLB 확보 문제를 짚은 의견이 엔진 설계와 직결된다.
- **C = 소셜.** 포스트잇에 방명록과 배치 제안을 합치자는 제안이 현재 소셜 설계의 바탕이다.
- **D가 웹 추천 화면도 맡는다 (11/25).** 12/11 마감으로 B의 3주차 몫(4개)이 몰렸고, D는 엔진 Must를 다 끝냈다. 그래서 엔진 결과를 그대로 화면에 보여 주는 #25(취향 질문 + 배치안 카드 3개)와 #29(마켓 패널·구매 링크)를 D가 `apps/web/src/recommend/`에서 만든다. B는 #21 가구 편집, #23 템플릿 선택 UI에 집중한다.
- **B = 웹 뷰어.** 모든 파트가 결과를 보여 주는 화면이라 기능 수가 가장 많다. 3주차 몫이 가장 많아서, 막히면 E나 A가 나눠 맡는다.

역할을 바꾸면 이 파일을 고친다. `.github/CODEOWNERS`는 역할별이 아니라 승인이 필요한 공통 경로만 적으므로, E가 바뀔 때만 같이 고친다.
