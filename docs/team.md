## 배정 기준

- **E = 전체 확인 역할.** E는 모든 파트의 PR을 최종 확인하고 통합 데모(2·4·6주차)를 이끈다. 그래서 E의 구현 범위는 API·인증·저장·배포로 좁히고, 손이 많이 가는 데이터 작업(템플릿·카탈로그 수집)은 A로 옮겼다.
- **A = iOS + 데이터.** iOS 앱은 화면 4개 규모라 작업량이 적다. 대신 LiDAR 기기로 팀원 방을 실측하고, 카탈로그 25종(규격·가격·URL)을 시트로 수집해 E에게 넘긴다.
- **D = 엔진.** 점수 요소, LLM 설명, GLB 확보 문제를 짚은 의견이 엔진 설계와 직결된다.
- **C = 소셜.** 포스트잇에 방명록과 배치 제안을 합치자는 제안이 현재 소셜 설계의 바탕이다.
- **B = 웹 뷰어.** 모든 파트가 결과를 보여 주는 화면이라 기능 수가 가장 많다. 5주차 Should는 상황에 따라 E가 나눠 맡는다.

역할을 바꾸면 이 파일과 `.github/CODEOWNERS`를 같이 고친다.
