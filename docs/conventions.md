# 좌표·단위·ID 규약

어기면 통합 때 방이 뒤집히거나 가구가 벽을 뚫는다. 루트 `CLAUDE.md`에도 같은 표가 있다.

| 항목 | 규약 |
| --- | --- |
| 단위 | 모든 길이는 **mm 정수**. Three.js 렌더 시 `/ 1000`, RoomPlan(m) → `round(x * 1000)` |
| 축 | 오른손 좌표계, **Y축 = 위**, 바닥 = XZ 평면 (RoomPlan·Three.js 공통) |
| 2D 평면 좌표 | `{ x, z }` (mm). 평면도에서 위쪽이 −Z |
| 원점 | 바닥 다각형 바운딩 박스의 최소 (x, z) = (0, 0). iOS 변환기가 평행이동 |
| 회전 | `rotationDeg`: Y축 기준 반시계 방향. MVP는 0/90/180/270만 |
| 가구 기준점 | 바닥면 중심. `width`=X, `depth`=Z, `height`=Y (회전 0도 기준) |
| 가구 정면 | 회전 0도일 때 +Z (책상은 사람이 앉는 쪽, 수납장은 문 열리는 쪽) |
| `.glb` 모델 | m 단위, 바닥면 중심이 원점, 정면 +Z. 어기면 카탈로그 등록 거부 |
| 벽 선 (`walls[].start`→`end`) | **방 안쪽 면**의 선이다 (바닥 윤곽 `floorPolygon`의 변과 같은 선). 벽 두께 `thickness`는 방 바깥쪽으로 붙는다. 그래서 바닥 윤곽 치수 = 실제로 쓸 수 있는 방 안쪽 치수 |
| 개구부 `offset` | 벽 `start`에서 개구부 시작 모서리까지 거리 |
| 문 `hingeSide` | **방 안쪽에 서서 문을 바라볼 때 왼손 쪽이 `left`**. 웹 렌더(#54)와 엔진 제약 검사(#56)가 이 기준으로 계산한다 |
| 가구 `clearance.left/right` | **가구 정면에 서서 가구를 바라볼 때** 왼쪽·오른쪽. 회전 0도에서 `left` = −X, `right` = +X |
| 포스트잇 `point` | mm. 가구에 붙으면 그 가구 기준 로컬 좌표 |
| ID | `prefix_` + ULID: `room_`, `lay_`, `pin_`, `cat_`, `inst_`, `user_`, `guest_` |
| 시간 | ISO 8601 UTC |
| 마켓 여유 폭 | 정밀 모드(`source = lidar`) 20mm, 자유 모드 50mm |
| 폴리곤 예산 | 방 전체 50k 삼각형 이하, `.glb` 하나당 5k 이하, Draco 압축 |
